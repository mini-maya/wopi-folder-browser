== Purpose and Scope

This document describes the current target architecture with multi-storage support
(`documents` + `external`) and a provider-capable storage layer.

Focus areas:

* clear separation of UI, API, WOPI, and storage
* unique document identity per storage
* secure path resolution (traversal/symlink protection)
* read-only and availability behavior
* extensibility for future providers (WebDAV/SMB/S3)

== Storage Model

Example configuration (persisted in `WOPI_STATE_ROOT/common/storages.json`):

[source,json]
----
{
  "storages": [
    {
      "id": "documents",
      "name": "Documents",
      "type": "local",
      "root": "/documents",
      "enabled": true,
      "readOnly": false,
      "system": true
    },
    {
      "id": "external",
      "name": "External Storage",
      "type": "local",
      "root": "/external/storage",
      "enabled": true,
      "readOnly": false,
      "system": false
    }
  ]
}
----

Key rules:

* `id` is stable and technically relevant.
* `name` is presentation only.
* `root` is always a container path, never a host path.
* `enabled=false` disables a storage at runtime.
* `readOnly=true` blocks mutating operations.

== Request Routing and Storage Resolution

Storage is resolved using:

1. URL prefix `/storage/<id>`
2. Header `X-Storage-Id`
3. Query `storageId`
4. Session `selectedStorageId`
5. Fallback `documents`

[plantuml, request-storage-resolution-en, svg]
....
@startuml
skinparam shadowing false
start
:incoming request;
if (path starts with /storage/<id>?) then (yes)
  :use id from path;
elseif (X-Storage-Id present?) then (yes)
  :use id from header;
elseif (query storageId present?) then (yes)
  :use id from query;
elseif (session selectedStorageId?) then (yes)
  :use id from session;
else (fallback)
  :use documents;
endif

:StorageManager.resolveOrHttpError(id);
if (available?) then (yes)
  :attach req.storage;
else (no)
  :API/WOPI -> error;
  :UI routes -> safe fallback;
endif
stop
@enduml
....

== Storage-Related API Surfaces

=== Public API

* `GET /api/storages` +
  returns storage metadata without internal `root` paths.
* existing document APIs execute against the currently resolved storage.

=== Admin API

* `GET /api/admin/external-acl` +
  returns the current `allowedUserIds` for the external storage.
* `POST /api/admin/external-acl` +
  updates the external-storage allowlist.

== Security Architecture

=== Access Control Matrix

The application implements a role-based access control system across four storage types:

[cols="1,2,2,2,2", options="header"]
|====
| Storage | Anonymous | Auth User | Admin | Notes
| `documents` | ❌ | ✅ User-scoped | ✅ | Per-user isolation in `/documents/users/<userId>/`
| `shared` | Mode-dependent | Mode-dependent | ✅ | Configurable: disabled/auth/readonly/readwrite
| `external` | ❌ | ACL-dependent | ✅ | Empty ACL = all auth users; filled ACL = whitelist only
| `recycle` | ❌ | ✅ Same user | ✅ | Per-user recycle bin
|====

=== Shared Storage Mode (Configurable)

The `shared` storage is configured via `SHARED_STORAGE_MODE` environment variable:

* `disabled` (default): not visible, not accessible
* `auth`: visible only to authenticated users, read-write
* `readonly`: visible to all (including anonymous), read-only
* `readwrite`: visible to all (including anonymous), read-write

=== Per-User Document Root Isolation

Authenticated users automatically receive an isolated document root:

----
Host:    /srv/wopi/documents/
         └─ user1/
         └─ user2/

Container: /documents/users/
           └─ <user-id-1>/    (only User 1 sees this content)
           └─ <user-id-2>/    (only User 2 sees this content)
----

Unauthenticated requests/shares use a shared root: `/documents/shared`

=== External Storage ACL

`external` storage is configured with `allowedUserIds` (persisted in `storages.json`):

* Empty ACL: All authenticated users can access
* Filled ACL: Only user IDs in the list can access
* Unauthenticated users: Always denied (403)

Administration via `/api/admin/external-acl`:
----
GET /api/admin/external-acl
    → { "allowedUserIds": ["alice", "bob"] }

POST /api/admin/external-acl
    → { "allowedUserIds": ["alice"] }
    → Persisted in storages.json
----

=== Path Security

Central rules in `lib/storage/storagePath.js`:

* relative paths only
* no absolute paths
* no `.` / `..` traversal segments
* backslashes are normalized and validated
* parent `realpath` check prevents symlink escapes

[plantuml, path-security-en, svg]
....
@startuml
skinparam shadowing false
start
:input relativePath;
:normalize (/ + \\ handling);
if (absolute?) then (yes)
  :reject;
  stop
endif
if (contains . or .. segments?) then (yes)
  :reject;
  stop
endif
:resolve candidate under root;
if (candidate outside root?) then (yes)
  :reject;
  stop
endif
:realpath(existing parent);
if (parent outside root?) then (yes)
  :reject;
  stop
endif
:safe absolute path;
stop
@enduml
....

=== Read-Only Enforcement

* Backend blocks mutating operations (API + WOPI).
* Provider centrally blocks write/delete/rename/copy/mkdir.
* UI disables mutating actions for read-only storages.

== Operational Notes

* If `/external/storage` is missing, the app stays available; the storage is marked unavailable.
* Host paths are never exposed through API or frontend.
* Startup logs include per-storage health status.
